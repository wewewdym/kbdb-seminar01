# Подготовка к защите семинара 1

## Что показать преподавателю

Открой репозиторий, запусти Docker и выполни:

```bash
docker compose up -d
docker compose ps
make run
```

Покажи файл `sql/seminar01.sql`, результаты запросов 1–7 и найденные проблемы качества данных.

## Текст для объяснения

«Я развернула PostgreSQL в Docker и изучила учебную базу компрессорных станций: площадки, агрегаты, датчики, измерения, события и ремонты. В SQL-запросах использованы JOIN, LEFT JOIN, COUNT, AVG, MAX, GROUP BY, HAVING и NOT EXISTS. Например, LEFT JOIN сохраняет агрегаты без датчиков, а NOT EXISTS помогает найти агрегаты без аварий. Обнаружились ошибки качества данных: Alarm с заглавной буквы и warning с лишним пробелом. Для корректной проверки использовала LOWER(TRIM()).»

## Задачи 1–7

1. JOIN — связь агрегата с площадкой; ORDER BY — сортировка.
2. LEFT JOIN + COUNT(s.id) — подсчёт датчиков, в том числе ноль.
3. JOIN двух таблиц + AVG + ROUND — средняя температура.
4. WHERE отбирает температурные строки до группировки; HAVING проверяет максимум после группировки.
5. date_trunc('hour', ts) — группировка измерений по часам.
6. GROUP BY по площадке и severity — число событий каждого уровня.
7. NOT EXISTS — отсутствие событий alarm и unplanned_stop; LOWER(TRIM()) нормализует регистр и пробелы.

## Частые вопросы

**JOIN против LEFT JOIN?** JOIN возвращает совпавшие записи, LEFT JOIN дополнительно сохраняет все строки слева.

**Почему COUNT(s.id), а не COUNT(*)?** При отсутствии датчика LEFT JOIN возвращает строку с NULL справа. COUNT(*) посчитал бы 1, COUNT(s.id) — 0.

**WHERE и HAVING?** WHERE фильтрует строки до агрегирования, HAVING — сгруппированные результаты.

**PK и FK?** Первичный ключ уникально идентифицирует запись. Внешний ключ обеспечивает ссылку на существующую родительскую запись.

**NOT EXISTS?** Проверяет, что подзапрос не вернул строк; подходит для поиска агрегатов без аварий.

**Какие проблемы данных?** Разное написание severity, датчик без измерений, агрегат без датчиков, вероятные дубли ремонтов.

**Почему не удаляем подозрительные дубли?** Похожая дата и описание не гарантируют, что это одна и та же работа; нужна предметная проверка.
